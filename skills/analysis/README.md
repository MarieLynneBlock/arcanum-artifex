# Analysis Skills

This category contains skills for structured analysis tasks such as audits, tradeoff analysis, and decision framing.

## Skills

| Skill | Description |
| --- | --- |
| [architecture-audit](architecture-audit/SKILL.md) | Structured audit of a system design or ADR against quality attributes, with prioritised findings and recommendations. |
| [tradeoff-analysis](tradeoff-analysis/SKILL.md) | Compare options against weighted criteria and produce a transparent recommendation with stated conditions. |
| [risk-analysis](risk-analysis/SKILL.md) | Identify, score, and prioritise risks across technical, operational, security, compliance, delivery, and people dimensions. |
| [write-user-story](write-user-story/SKILL.md) | Draft a well-formed user story (Connextra format) with INVEST validation, Given/When/Then acceptance criteria, and a definition of done. |
| [write-epic](write-epic/SKILL.md) | Define an agile epic with a goal statement, in/out-of-scope boundaries, success metrics, and an initial story map. |
| [miro-board](miro-board/SKILL.md) | Generate a Miro board via REST API (Python) or a structured Miro AI prompt for analyst deliverables: story maps, process flows, stakeholder maps, gap analysis, and matrices. |
| [gap-analysis](gap-analysis/SKILL.md) | Compare current state to target state across dimensions (process, data, technology, people, compliance), score gaps by severity, and produce prioritised recommendations. |
| [process-map](process-map/SKILL.md) | Document AS-IS or TO-BE processes as Mermaid swim-lane flowcharts with decision points, handoffs, and a companion process narrative. |
| [stakeholder-map](stakeholder-map/SKILL.md) | Map stakeholders on an influence × interest grid, classify engagement stance, flag alignment risks, and produce an engagement strategy per quadrant. |
| [use-case](use-case/SKILL.md) | Write a formal use case (Cockburn format) with actors, preconditions, numbered main success scenario, extension flows, and business rules. |
| [requirements-document](requirements-document/SKILL.md) | Produce a BRD or FRS with business context, stakeholder needs, functional and non-functional requirements, constraints, assumptions, and a traceability matrix. |
| [acceptance-test-plan](acceptance-test-plan/SKILL.md) | Generate a traceable acceptance test plan with happy path, edge case, and negative test cases derived from user stories, use cases, or functional requirements. |

## Add a skill here

1. Copy the template from `../../templates/skills/skill_blank/`.
2. Use a scope-first name (for example `architecture-audit` or `risk-analysis`).
3. Define expected outputs and evidence standards.
