## Stack

- Language: C# (.NET Framework 4.x / .NET 6+ depending on OutSystems version)
- Tool: OutSystems Integration Studio
- Target: OutSystems [O11 / ODC] platform
- Test: xUnit / MSTest for unit-testable logic

## OutSystems extension conventions

- Every public method exposed as an OutSystems Action must match the signature defined in Integration Studio exactly — name, parameter order, and types.
- Use `ssXxx` naming for action parameters as generated by Integration Studio. Do not rename generated parameters.
- Wrap all extension logic in try/catch and throw `OutSystems.HubEdition.RuntimePlatform.OsRuntimeException` (O11) or the equivalent ODC exception for errors surfaced to OutSystems flows.
- Do not use `Console.WriteLine` or file I/O for logging — use the OutSystems platform logging API or return error messages via output parameters.
- Actions must be stateless — no static mutable fields. Integration Studio extensions can be called concurrently.

## Integration Studio project structure

```text
<ExtensionName>/
├── <ExtensionName>.xif         ← Integration Studio project file (do not hand-edit)
├── Source/
│   └── NET/
│       ├── <ExtensionName>.cs  ← main action implementations
│       └── *.cs                ← supporting classes
└── Bin/
    └── <ExtensionName>.dll     ← built output (do not commit)
```

- All action implementations go in the `Source/NET/` directory.
- The `.xif` file is managed by Integration Studio — only edit via the IDE, not by hand.
- Do not commit `Bin/` output — add to `.gitignore`.

## Type mapping (OutSystems → C#)

| OutSystems type | C# type |
| --- | --- |
| Text | `string` |
| Integer | `int` |
| Long Integer | `long` |
| Decimal | `decimal` |
| Boolean | `bool` |
| Date Time | `DateTime` |
| Binary Data | `byte[]` |
| Record / Structure | Generated class (e.g. `RCMyStructureRecord`) |
| Record List | `RLMyStructureRecordList` |

Always use the generated `RC` / `RL` prefixed classes for Structures and Record Lists — do not substitute plain C# classes.

## Naming conventions

- Action classes: `Css<ExtensionName>` (generated by Integration Studio — do not rename).
- Action methods: match the OutSystems action name exactly, prefixed with `Mss` (e.g. `MssGetUserById`).
- Input parameters: `ss<ParamName>` (e.g. `ssUserId`).
- Output parameters: `ss<ParamName>` passed as `out` or `ref`.
- Internal helper methods: `PascalCase`, no `ss` prefix.

## Error handling

```csharp
try {
    // action logic
} catch (Exception e) {
    throw new OutSystems.HubEdition.RuntimePlatform.OsRuntimeException(
        "<ExtensionName>", e);
}
```

Always wrap the full action body. OutSystems surfaces the exception message in the platform — keep messages clear and actionable.

## What not to do

- Do not rename generated `ss`-prefixed parameters — Integration Studio will lose the mapping.
- Do not use `async`/`await` in action methods — OutSystems calls extensions synchronously.
- Do not store session or user state in static fields — actions are called concurrently.
- Do not reference `System.Web` — extensions run outside IIS in ODC; use platform APIs instead.
- Do not hand-edit the `.xif` file — always use Integration Studio for structural changes.
